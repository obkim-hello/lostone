## 1. Technical Goals

- Build a **production model-management UI** as a thin driver over Module 007's `ModelRepository` — never re-implement download/storage/activation; only call its API and render its `Stream<InstallEvent>`.
- Define and own the **settings contract**: `RuntimeChoice`, `AppSettings`, `SettingsRepository`, persisting non-secrets in Hive and secrets in Flutter Secure Storage.
- **Expose** `PersonaRuntimeMode` + `cloudAuthorized` (+ `activeModelId`) via a Riverpod provider so Modules 006 (chat) and 009 (distill) can watch a single source of truth.
- Keep state deterministic and host-testable: all external effects (`ModelRepository`, secure storage, Hive) behind interfaces injected via providers, so host tests use a fake repository with scripted `InstallEvent` streams and in-memory settings.
- Surface every `InstallErrorKind` distinctly — no silent failures.

---

## 2. Design Constraints

- **No new backend.** Model download/storage/activation is 007; inference/authorization enforcement is 004. 010 is UI + settings persistence only.
- **Secret isolation (ADR-002/004).** Cloud API key and HF token go **only** to Flutter Secure Storage; never Hive, never logs. Hive holds only non-secret `AppSettings`.
- **Local by default.** First-run `AppSettings`: `runtime == local`, `cloudAuthorized == false`, `activeModelId == null`.
- **Riverpod style (pinned).** Legacy `StateNotifier<State>` + top-level `final StateNotifierProvider<Notifier, State>`; `StateProvider` for trivial config (match `app_providers.dart` / `import_providers.dart`). Immutable state; constructor-injected services with defaults.
- **Navigation (pinned).** No router; imperative `Navigator.of(context).push(MaterialPageRoute(...))`. `go_router` is Technical Debt (§11).
- **Device reality (ADR-005).** iOS 16.0+; simulator/host tier (`simulatorCpu`) can only run SmolLM 135M — 1B/E2B are over-tier there. Quality UAT is on-device.
- **Production store gap (DD-002).** The harness wires `InMemoryModelStore`; production needs a disk-backed `ModelStore`, and `freeBytes` precheck has no host/`dart:io` API (§11).

## 3. Architecture

### 3.1 Component diagram

```
[App bar / Module 009 library]  ── push ──►  [SettingsScreen]
        ▲ "install a model" prompts (006/009)        │
        │                                            ├─ Runtime & Privacy section
        │                                            │     └─ SettingsNotifier ──► SettingsRepository (Hive)
        │                                            │                         └─ SecureKeyStore (Secure Storage: cloud key)
        │                                            ├─ Models section
        │                                            │     └─ ModelManagerNotifier ──► ModelRepository (Module 007)
        │                                            │            (subscribes Stream<InstallEvent>)
        │                                            │            └─ SecureTokenStore (Secure Storage: HF token)
        │                                            └─ Advanced (temperature) ──► SettingsNotifier
        │
[appSettingsProvider]  ◄── watch ──  [Module 006 ChatOptions] / [Module 009 LlmBuildOptions]
```

### 3.2 Component design

- **`SettingsScreen`** — the entry surface (Runtime & Privacy / Models / Advanced sections). Imperative `Navigator` push from app bar / 009 home. Reads `appSettingsProvider`, dispatches to notifiers.
- **`ModelManagementScreen`** (section or pushed page) — renders the catalog + installed lists from `ModelManagerNotifier`; per-row Install/Cancel/Activate/Delete; determinate progress from `InstallEvent`; typed error rows.
- **`SettingsNotifier extends StateNotifier<AppSettings>`** — loads via `SettingsRepository` on construction, exposes `setRuntime`, `setCloudAuthorized`, `setCloudApiKey`, `setHfToken`, `setActiveModelId`, `setChatTemperature`; persists non-secrets via `SettingsRepository`, secrets via the injected secure stores. State is `AppSettings` (secrets are **not** part of state; presence is exposed as booleans).
- **`ModelManagerNotifier extends StateNotifier<ModelManagerState>`** — wraps `ModelRepository`; `refresh()` snapshots catalog/installed/active; `install(id)` subscribes to `install(...)` and folds `InstallEvent` into per-model progress/state; `cancel/delete/activate` proxy the repository and re-snapshot. On `setActive` success it calls `SettingsNotifier.setActiveModelId` to mirror into `AppSettings`.
- **Providers** — `settingsRepositoryProvider`, `modelRepositoryProvider` (assembles the production `DefaultModelRepository` with a **disk-backed** `ModelStore`), `appSettingsProvider` (`StateNotifierProvider<SettingsNotifier, AppSettings>`), `modelManagerProvider` (`StateNotifierProvider<ModelManagerNotifier, ModelManagerState>`).

### 3.3 Module dependencies

| Module | Interface used | Purpose |
|--------|----------------|---------|
| 007 | `ModelRepository` (`catalog`/`install`/`cancel`/`delete`/`setActive`/`getActiveModelHandle`/`installed`/`stateOf`), `ModelDescriptor`/`InstalledModel`/`InstallEvent`/`ModelState`/`InstallErrorKind`/`DeviceTier`, `DeviceCapabilities`, `ModelStore`, `SecureTokenStore` | Model management backend + HF token |

## 4. Data Structures

### 4.1 Core models

```dart
/// User-facing runtime choice; maps 1:1 to Module 004 PersonaRuntimeMode.
enum RuntimeChoice { local, cloud, maxPrivacy }

PersonaRuntimeMode toRuntimeMode(RuntimeChoice c) => switch (c) {
      RuntimeChoice.local => PersonaRuntimeMode.local,
      RuntimeChoice.cloud => PersonaRuntimeMode.cloud,
      RuntimeChoice.maxPrivacy => PersonaRuntimeMode.maxPrivacy,
    };

@immutable
class AppSettings {
  const AppSettings({
    this.runtime = RuntimeChoice.local,
    this.cloudAuthorized = false,
    this.activeModelId,
    this.chatTemperature = 0.7,
  });

  final RuntimeChoice runtime;      // default local
  final bool cloudAuthorized;       // opt-in, default false
  final String? activeModelId;      // mirror of 007 active handle id
  final double chatTemperature;     // optional advanced

  AppSettings copyWith({
    RuntimeChoice? runtime,
    bool? cloudAuthorized,
    Object? activeModelId = _sentinel,  // nullable-aware copy
    double? chatTemperature,
  });

  PersonaRuntimeMode get runtimeMode => toRuntimeMode(runtime);
  // == / hashCode over all four fields.
}
```

`ModelManagerState` (immutable): `{ List<ModelDescriptor> catalog, List<InstalledModel> installed, String? activeModelId, Map<String, InstallProgress> progress, InstallFailure? lastError }`, where `InstallProgress { ModelState state, int receivedBytes, int totalBytes }` and `InstallFailure { String modelId, InstallErrorKind kind }`. `progress[id]` derives from `InstallEvent`; `installed`/`catalog`/`activeModelId` snapshot the repository.

### 4.2 Settings persistence

- **`SettingsRepository`** (owned contract):

```dart
abstract class SettingsRepository {
  Future<AppSettings> load();          // returns defaults if none stored
  Future<void> save(AppSettings settings);
}
```

- **`HiveSettingsRepository`** — reads/writes a `settings` Hive box, one scalar per field: `runtime` (enum index/name), `cloudAuthorized` (bool), `activeModelId` (String?), `chatTemperature` (double). Missing keys → defaults. **Contains no secret fields.**
- **`InMemorySettingsRepository`** — host-test fake backed by an in-memory `AppSettings`.
- **Secrets** — `SecureKeyStore` (cloud API key) uses the same Flutter Secure Storage mechanism as the existing `SecureTokenStore` (HF token), under distinct keys (e.g. `cloud_api_key`, HF token via `SecureTokenStore`). Secrets are never members of `AppSettings` (so they never enter Hive); the notifier exposes only `bool hasCloudKey` / `bool hasHfToken` in derived UI state.

### 4.3 Storage format

| Store | Key(s) | Type | Notes |
|-------|--------|------|-------|
| Hive `settings` box | `runtime` | String (enum name) | default `local` |
| | `cloudAuthorized` | bool | default `false` |
| | `activeModelId` | String? | mirror of 007 active |
| | `chatTemperature` | double | default `0.7` |
| Secure Storage | `cloud_api_key` | String | via `SecureKeyStore`; never Hive/logs |
| Secure Storage | HF token | String | via existing `SecureTokenStore` |
| App documents dir | model files | binary | owned by 007 `ModelStore` (not 010) |

## 5. Interface Design

```dart
// Owned by 010.
enum RuntimeChoice { local, cloud, maxPrivacy }

abstract class SettingsRepository {
  Future<AppSettings> load();
  Future<void> save(AppSettings settings);
}

// Secure secret access (thin; mirrors TokenStore shape).
abstract class SecureKeyStore {
  Future<String?> read();
  Future<void> write(String key);
  Future<void> clear();
}

class SettingsNotifier extends StateNotifier<AppSettings> {
  SettingsNotifier({
    required SettingsRepository repository,
    required SecureKeyStore cloudKeyStore,
    required TokenStore hfTokenStore,   // reuse SecureTokenStore
  });

  Future<void> loadInitial();          // repository.load() → state
  Future<void> setRuntime(RuntimeChoice c);
  Future<void> setCloudAuthorized(bool v);
  Future<void> setCloudApiKey(String key);   // → SecureKeyStore, not state
  Future<void> clearCloudApiKey();
  Future<void> setHfToken(String token);     // → SecureTokenStore
  Future<void> setActiveModelId(String? id);
  Future<void> setChatTemperature(double t);
}

class ModelManagerNotifier extends StateNotifier<ModelManagerState> {
  ModelManagerNotifier({
    required ModelRepository repository,
    required DeviceCapabilities device,
    void Function(String? id)? onActiveChanged,  // → SettingsNotifier.setActiveModelId
  });

  Future<void> refresh();
  Future<void> install(String modelId, {String? hfToken, bool allowOverTier = false});
  Future<void> cancel(String modelId);
  Future<void> delete(String modelId);
  Future<void> activate(String modelId);
}

// Providers (top-level, pinned style):
final Provider<SettingsRepository> settingsRepositoryProvider;
final Provider<ModelRepository> modelRepositoryProvider;   // disk-backed ModelStore
final StateNotifierProvider<SettingsNotifier, AppSettings> appSettingsProvider;
final StateNotifierProvider<ModelManagerNotifier, ModelManagerState> modelManagerProvider;
```

Modules 006/009 read via `ref.watch(appSettingsProvider)` → `runtimeMode` + `cloudAuthorized` (+ `chatTemperature`, `activeModelId`).

## 6. Implementation Details

### 6.1 Key algorithms / flows

**Install (fold `InstallEvent`):**
1. Precheck device fit: if `!device.canRun(descriptor)` and not `allowOverTier`, the UI first requires an over-tier confirm (A1). On confirm, call `install(id, allowOverTier: true)`.
2. Resolve HF token: gated model (`descriptor.requiresToken`) → pass the stored HF token; if absent, 007 emits `failed(authRequired)` which the notifier maps to an actionable "enter token" row (do not block the call — surface the typed error).
3. Subscribe to `repository.install(id, hfToken:, allowOverTier:)`; for each `InstallEvent` update `progress[id] = {state, receivedBytes, totalBytes}`. On `state == failed`, set `lastError = {id, event.error ?? unknown}`.
4. On stream done, if `stateOf(id) == ready`, refresh installed list; the user may then activate.

**Activate/switch:** `repository.setActive(id)` (ready-only; catches `StateError`) → `refresh()` → `onActiveChanged(id)` → `SettingsNotifier.setActiveModelId(id)` (Hive mirror). `getActiveModelHandle()` remains the source of truth; `AppSettings.activeModelId` is a mirror for display/restore.

**Delete active:** confirm → `repository.delete(id)` (idempotent; cancels any in-flight) → if `id == state.activeModelId`, `onActiveChanged(null)`. `refresh()`.

**Cancel mid-install:** `repository.cancel(id)` → 007 cleans the half-download and emits `notInstalled`; notifier clears `progress[id]`.

**Mode/auth persistence:** each setter builds `state.copyWith(...)`, assigns `state`, and awaits `repository.save(state)`. Cloud key setters write only to `SecureKeyStore` and do not mutate `AppSettings`.

### 6.2 State management

- `SettingsNotifier` seeds from `repository.load()` (defaults if empty) in `loadInitial()` (called by the provider). All mutations are `copyWith` + `save`; the provider is the single source read by 006/009.
- `ModelManagerNotifier` holds ephemeral install progress (not persisted) + snapshots; only `activeModelId` crosses into persisted settings via the callback.
- Secrets never enter either notifier's immutable state — presence-only booleans are computed for the UI.

### 6.3 Error handling

Map `InstallErrorKind` to distinct UI (no silent failures):

| `InstallErrorKind` | UI state | Action |
|--------------------|----------|--------|
| `authRequired` | "Hugging Face token required" | focus/route to HF token field |
| `insufficientStorage` | "Not enough storage" | free space / delete a model |
| `unsupportedDevice` | "May not run on this device" | over-tier confirm (`allowOverTier`) or pick a smaller model |
| `network` | "Download failed (network)" | retry |
| `corrupted` | "File verification failed" | retry (re-download) |
| `canceled` | back to not-installed | (none; user-initiated) |
| `unknownModel` | "Unknown model" | (defensive; catalog-driven so unexpected) |
| `unknown` | "Install failed" | retry |

`setActive` on a non-ready model (`StateError`) is caught and shown as "model not ready". `SettingsRepository`/secure-store failures surface as a non-fatal snackbar; the in-memory state still reflects the intended value but a save-failed indicator is shown (never swallowed).

### 6.4 Logging

- No secret is ever logged: cloud API key and HF token are never printed (not even length/prefix beyond a redacted marker). Log lines about install use `modelId` + `state` + `error.name` only (as the harness does).
- Optional `onLog` hook on notifiers for host-test observability; defaults to no-op.

## 7. Test Strategy

- **Unit/contract (host, coverage > 80%)**: `SettingsRepository` round-trip (defaults, save→load), secret isolation (assert secrets go to the fake secure store and never into the Hive map); `SettingsNotifier` transitions (mode/auth/temperature, cloud-without-key derived state, `activeModelId` mirror); `ModelManagerNotifier` with a **fake `ModelRepository`** emitting scripted `InstallEvent` streams — progress fold, each `InstallErrorKind`, activate/switch, delete-active clears active, cancel mid-install.
- **Widget (host)**: model management + settings screens with fakes — catalog renders recommended-first, determinate progress bar, typed error rows, confirm-delete dialog, obscured secret fields, mode selector persistence.
- **On-device (staged, ADR-005)**: install Gemma 3 1B with a real HF token; activate; confirm 006 chat + 009 distill read mode/auth from `appSettingsProvider`.

## 8. Performance

- Install progress events rendered within 007's < 500ms callback budget (PRD-007 §4.1); no list jank during download.
- `SettingsRepository.load/save` are async, local (Hive), sub-frame on app start.
- Catalog/installed rendering O(n) over a small catalog; `stateOf`/`usedBytes` are O(1)~O(n).

---

## 9. Security

- Secrets only in Flutter Secure Storage (cloud API key via `SecureKeyStore`, HF token via `SecureTokenStore`); never Hive, never logs.
- Local-by-default defaults; cloud strictly opt-in; a network call is impossible without `authorized == true` + a stored key (`CloudRuntime` gate, Module 004).
- No model network request without an explicit user install tap (007 only downloads on request).
- 010 persists only inference configuration — no chat/persona/import content.
- Model-file encryption / backup exclusion is Module 008 (007 provides the hooks); 010 does not weaken them.

---

## 10. Deployment

- iOS 16.0+ (ADR-005); relies on 007's platform assembly (entitlements, `UIFileSharingEnabled`, static-linked pods).
- Providers assemble the production `DefaultModelRepository(catalog: ModelCatalog(), installer: FlutterGemmaInstaller(), store: <disk-backed ModelStore>, device: DeviceCapabilities(...), tokenStore: SecureTokenStore())` — note: **not** `InMemoryModelStore` (that is host-only).
- Settings + secrets initialized at app start (Hive box opened, secure stores available) before `appSettingsProvider` is read.
