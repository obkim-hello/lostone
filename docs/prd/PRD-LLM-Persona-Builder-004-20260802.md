## 1. 背景与目标

### 1.1 背景

模块 003 交付了纯 Dart、离线、确定性、无 LLM 的**统计五层 Persona 引擎**。我们随后用一段真实微信语料（1124 条对方消息，`confidence=high`）做了同语料双方法实证对比：

- **统计引擎输出**（`persona.json`）：只抓到表层词频（"哈哈""不错""是的"），且**捏造了情感特征**——所谓"关心型/温柔安慰"是对"记得""没事"等词的无上下文命中；产出碎片噪音与无意义的重复记忆（"提及生日 ×8"）。真人验证结论："does not feel like her at all（完全不像她）"。
- **LLM 蒸馏输出**（`persona_exskill.md`，参照 ex-skill 方法论）：抓到了她的签名特征（爱反问"你呢""这在哪里"）、真实例句、生活背景（多伦多、金融 wealth 组、3 小时通勤、闺蜜），并在素材不足处诚实标注。明显更像本人。

**核心结论**：人格的关键信息在于"**词语在上下文中如何被使用**"，只有 LLM 通读原始记录才能保留；纯统计词频无法编码性格，且会无中生有。详见 ADR-004。

因此，人格的"正式生成"应改为 **LLM 蒸馏**：读原始消息，按五层模板产出忠实、含真实例句、诚实标注不确定性的人格；模块 003 统计引擎**保留**并降级为预处理与离线兜底。

### 1.2 目标

- 从一段 `Conversation` 用 **LLM 蒸馏**出"读起来就像本人"的五层 Persona，取代统计人格，作为送入下游对话 LLM（模块 006）的正式人格。
- **运行时混合策略落地**：默认**本地 LiteRT**（隐私优先、原文不出设备），**云端 API 为显式 opt-in**（质量优先，须用户明确授权）。这是 ADR-002 的具体实现。
- **输出契约不变**：复用模块 003 的 `Persona` 模型与 `PromptTemplate` 渲染契约，使蒸馏结果在现有管道中即插即用，下游模块无需改动。
- **诚实性优先**：人格必须包含真实例句、可回溯到原始消息的依据；**素材不足时明确标注"原材料不足"而非编造具体事实**。
- 保留模块 003 统计引擎作为**预处理/离线兜底**：去重、message-key 哈希、表层统计，以及"无可用模型/最大隐私模式"下的兜底人格。

### 1.3 范围

**包含**：
- LLM 蒸馏人格生成：读原始消息 → 按五层模板产出忠实人格（含真实例句、生活背景、诚实的不确定性标注）。
- Runtime 抽象层：本地 LiteRT 与云端 API 的统一推理接口（对齐 ADR-002；**折叠原路线图"本地模型集成"/"云端 API 集成"两模块**）。
- 运行模式选择：默认本地、云端 opt-in、最大隐私（无模型时纯统计兜底）。
- 蒸馏结果到现有五层 `Persona` 的映射（HardRules / Identity / ExpressionStyle / EmotionalLogic / RelationalBehavior + Memories + tags）。
- 增量更新：对齐模块 003 现有 `update` 语义（哈希去重、版本递增、硬规则永不覆盖）。
- 素材不足/超长语料的处理（诚实标注、分块）。

**不包含**：
- 实际对话、消息生成、上下文管理、聊天 UI（属模块 006）。
- Persona 可视化/编辑界面（属 Phase 4 UI）。
- 模型下载/管理界面（属模块 007 模型管理）。
- 加密存储与生物识别（属模块 008；本模块只产出与模块 003 一致的 `Persona`/`.persona` 字节，交由存储层加密）。
- **修改或重写模块 003 统计引擎**：它按原样保留，仅被本模块作为预处理/兜底调用。
- 改动 `Persona` 模型对外形状与 `PromptTemplate` 契约（本模块必须适配现有契约，见 §3 功能 3、ERD §4）。

## 2. 用户故事

### 故事 1：丧亲用户 - LLM 蒸馏出"像本人"的人格

**作为**：一位导入了与已故母亲多年微信记录的用户
**我想要**：让 AI 通读这些记录，蒸馏出一个"说话、关心方式、生活背景都像妈妈"的人格
**以便于**：后续对话中感到"真的像她"，而不是一个抓词频的空壳

**验收标准**：
- [ ] 给定一段含足量目标人物消息的 `Conversation`，当选择生成，则产出的人格包含**真实例句**（"她会怎么说"）与可回溯到原始消息的签名特征。
- [ ] 给定生成结果，当查看，则人格**不含编造的具体事实**（未在原文出现的人名/地点/事件不得凭空出现）。
- [ ] 给定同一语料，统计引擎与 LLM 蒸馏并列对比时，LLM 结果在"像不像"主观评审上显著更优（UAT，见 §9.3）。

**优先级**：高

---

### 故事 2：隐私敏感用户 - 本地优先、云端可选

**作为**：一位在意隐私的用户
**我想要**：默认让蒸馏完全在本机完成，仅在我明确同意时才使用云端
**以便于**：原始聊天记录在默认情况下绝不离开我的设备

**验收标准**：
- [ ] 给定默认设置，当执行蒸馏，则全程使用本地 LiteRT，**原文不出设备**、无任何网络请求。
- [ ] 给定我未显式授权云端，当系统需要更高质量，则不得静默上传；必须先获得我对该次云端调用的明确同意。
- [ ] 给定我选择"最大隐私/无模型"模式，当执行，则回退到模块 003 统计兜底人格，仍能产出可用 `Persona`。

**优先级**：高

---

### 故事 3：用户 - 增量补充 - 不丢失已有回忆

**作为**：一位已生成 LLM 人格的用户
**我想要**：把新翻出来的旧记录追加进去
**以便于**：人格更完整，且不推翻我上次已认可的结果

**验收标准**：
- [ ] 给定已存在的 `Persona` 和一批新消息，当增量更新，则沿用模块 003 现有 `update` 语义：按消息键哈希去重、`personaVersion` 递增、追加 `revisions`。
- [ ] 给定用户已编辑的硬规则（HardRules），当增量更新，则**永不覆盖**。
- [ ] 给定重复导入相同消息，当更新，则去重、结果幂等。

**优先级**：中

---

### 故事 4：用户 - 理解生成依据 - 建立信任

**作为**：一位担心"AI 瞎编"的用户
**我想要**：看到人格结论的依据，以及素材不足时的诚实提示
**以便于**：相信这个人格真的来自我们的聊天，而非模型幻觉

**验收标准**：
- [ ] 给定任一签名结论/例句，当查看，则能定位到支撑它的原始消息（消息键哈希/短示例）。
- [ ] 给定某一层素材不足（少于阈值条原材料），当生成，则该层明确标注"原材料不足"（对齐现有 `confidence: low` + 文字提示），而非编造。

**优先级**：中

---

### 故事 5：开发者 - 契约不变 - 无缝替换

**作为**：模块 006（聊天）的实现者
**我想要**：LLM 蒸馏产物与模块 003 一样是标准 `Persona` / `PromptTemplate` 输出
**以便于**：无论人格来自统计还是 LLM，下游对话系统的接入方式完全一致

**验收标准**：
- [ ] 给定 LLM 蒸馏结果，当映射，则得到合法的 `Persona`（五层无 null、`schemaVersion==kPersonaSchemaVersion`），可被现有 `PersonaJsonCodec` 无损往返。
- [ ] 给定该 `Persona`，当调用现有 `PromptTemplate.render()`，则正常渲染为 system prompt，无需改动模板契约。

**优先级**：高

## 3. 功能清单

### 3.1 核心功能

#### 功能 1：LLM 蒸馏人格生成（LlmPersonaBuilder）
**描述**：读取（经模块 003 预处理的）原始目标人物消息，按 ex-skill 五层方法论构造蒸馏 prompt，调用 Runtime 产出忠实人格，再映射为标准 `Persona`。

**输入**：`Conversation`（模块 002 标准化 + 模块 003 预处理）+ 目标人物切分（复用模块 003 `splitBySender` 语义）+ `LlmBuildOptions`（运行模式/模型/温度/分块参数）。

**输出**：标准 `Persona`（五层 + tags + memories + `PersonaSource`）。

**业务规则**：
- 蒸馏必须保留**上下文中的用词方式**与**真实例句**；不得只做词频统计。
- **不得编造具体事实**：未在原文出现的人名/地点/事件/时间不得写入人格。
- 素材不足的层标注"原材料不足"（对齐 `confidence: low` + 文字说明）。
- 硬规则（HardRules）不由 LLM 生成覆盖用户设置；仅可补充建议项，最终以用户编辑为准。

**优先级**：P0

---

#### 功能 2：Runtime 抽象层（本地 LiteRT + 云端 API）
**描述**：统一的推理接口，屏蔽本地/云端差异，供功能 1 调用（落地 ADR-002）。

**输入**：蒸馏 prompt + 生成参数。

**输出**：模型文本响应（供功能 1 解析/映射）。

**业务规则**：
- 默认实现为**本地 LiteRT**（隐私优先）；云端实现为**显式 opt-in**。
- 统一接口暴露：模型可用性探测、生成、能力/上下文长度声明、错误分类。
- 云端调用前必须校验用户对该次调用的授权；本地调用不发起任何网络。
- 折叠原路线图"本地模型集成（旧 004）"与"云端 API 集成（旧 005）"的运行时职责于此层；对话时的模型使用（模块 006）复用同一抽象。

**优先级**：P0

---

#### 功能 3：蒸馏结果 → 五层 `Persona` 映射（契约适配）
**描述**：把 LLM 蒸馏的结构化产物映射到模块 003 现有 `Persona` 五层结构，保证契约不变。

**输入**：LLM 蒸馏产物（结构化字段/分层文本）。

**输出**：合法 `Persona`，可被现有 `PersonaJsonCodec` 编解码、被现有 `PromptTemplate` 渲染。

**业务规则**：
- 五层映射：LLM 抽取维度 → `HardRules`/`Identity`/`ExpressionStyle`/`EmotionalLogic`/`RelationalBehavior`；记忆 → `Memories`；性格标签 → `tags`。
- 真实例句/签名特征以现有可承载字段表达（如 `catchphrases`/`termsForUser`/`comfortPatterns`/`concernPatterns` 的 `TermStat`，`Memories.keyEvents`/`preferences`），并以 `Evidence`（消息键哈希）回溯。
- 输出 `schemaVersion == kPersonaSchemaVersion`；缺失层用空但存在的结构占位（不产 null 层）。
- **不改 `Persona`/`PromptTemplate` 对外形状**；如现有字段确不足以承载某类蒸馏信息，须在 ERD 记录并在契约兼容前提下扩展（新增可选字段、`schemaVersion` 前向兼容），不得破坏往返。

**优先级**：P0

---

#### 功能 4：运行模式与隐私门控
**描述**：让用户在"本地默认 / 云端 opt-in / 最大隐私（统计兜底）"之间选择，并强制隐私边界。

**输入**：用户运行模式选择、云端授权状态、可用模型状态。

**输出**：实际执行路径（本地蒸馏 / 云端蒸馏 / 统计兜底）。

**业务规则**：
- 默认本地；云端每次调用前需显式授权且提示"原文将上传至第三方"。
- 无可用模型或用户选最大隐私 → 回退模块 003 统计兜底，产出可用 `Persona` 并标注为统计来源/低置信。
- 任何路径都不得把原文写入日志。

**优先级**：P0

---

#### 功能 5：增量更新（复用模块 003 语义）
**描述**：对已存在 `Persona` 追加新消息，沿用模块 003 `update` 的去重/版本/合并语义。

**输入**：现有 `Persona` + 新 `Conversation`。

**输出**：更新后的 `Persona`（`personaVersion += 1`，追加 `revisions`）。

**业务规则**：
- 以消息键哈希去重保证幂等；硬规则永不覆盖。
- LLM 重蒸馏仅作用于受影响/新增素材；合并策略在 ERD/SPEC 细化（因 LLM 无 byte 确定性，合并以契约与结构断言校验，见 §9）。

**优先级**：P1

---

### 3.2 辅助功能

#### 功能 A：统计 vs LLM 双轨与兜底
**描述**：统计引擎（模块 003）既作为 LLM 蒸馏的预处理（去重/哈希/表层统计），又作为无模型时的兜底人格来源。

**优先级**：P1

#### 功能 B：诚实性与可回溯元数据
**描述**：为蒸馏结论附 `confidence`、"原材料不足"标注与 `Evidence`（消息键哈希/短示例），支撑故事 4。

**优先级**：P1

## 4. 非功能性需求

### 4.1 性能要求
- **本地蒸馏生成时间**：目标 ≤ 60 秒 / 1000 条消息（对齐 CLAUDE.md「Persona 生成」指标；受设备与模型影响，ERD 给分档目标）。
- **云端蒸馏**：端到端目标 ≤ 数分钟量级（含分块），并给出进度反馈（UI 属 Phase 4）。
- **首 token/推理速度**：本地对齐 CLAUDE.md（首 token < 2s、> 5 tokens/s @ iPhone 15+，作为 Runtime 目标）。
- **内存**：本地推理峰值 < 2GB（对齐 CLAUDE.md AI 推理内存指标）。

### 4.2 安全与隐私要求
- **本地路径原文不出设备**；云端路径须显式授权，且不记录敏感原文。
- 沿用模块 003 的 message-key 哈希做去重/溯源；`.persona` 不落逐条原文。
- 云端 API Key 使用 Flutter Secure Storage 加密（对齐 CLAUDE.md 安全要求）；日志不含完整 Key/原文。

### 4.3 可用性要求
- 无网络、无模型、素材不足、空会话等情况必须给出明确结果或错误，不崩溃、不编造；至少能回退到统计兜底。

### 4.4 兼容性要求
- 本地 LiteRT 随 Flutter 运行于 iOS/macOS（对齐 ADR-001/技术栈）。
- 输出 `Persona`/`.persona` 与模块 003 `schemaVersion` 兼容；契约保持向后兼容。

|--------|------|------|------|

| systemPrompt | `String` | 纯文本 | 由现有 `PromptTemplate` 渲染 |

### 5.3 数据存储
- 存储位置：应用私有目录（由存储层模块 008 管理、加密）。
- 存储格式：JSON（`.persona`），与模块 003 一致。
- 云端 API 凭据：Flutter Secure Storage。

## 6. 界面要求

> 本模块为引擎/推理层，无独立 UI（运行模式选择、云端授权、模型管理界面属 Phase 4 / 模块 007）。仅需保证：运行模式与授权状态可被上层查询；产物为标准 `Persona`，可被 UI 预览。

### 6.2 交互流程
```
（模块 002/003）导入 + 预处理完成 → 用户点击“生成人格”
  → 选择运行模式（本地默认 / 云端 opt-in / 最大隐私）
  → LlmPersonaBuilder.build(conversation)
      → 构造蒸馏 prompt（ex-skill 五层方法论）
      → Runtime 推理（本地 LiteRT / 云端 / 统计兜底）
      → 解析并映射为标准 Persona
  → 现有 PersonaJsonCodec 写 .persona / PromptTemplate 渲染
  → UI 展示（Phase 4）
```

## 8. 验收标准

### 8.1 功能验收
- [ ] LLM 蒸馏产出的人格含真实例句与可回溯依据，**不含编造具体事实**。
- [ ] 输出为合法 `Persona`，可被现有 `PersonaJsonCodec` 无损往返、被现有 `PromptTemplate` 渲染（契约不变）。
- [ ] 默认本地路径原文不出设备、无网络；云端为显式 opt-in。
- [ ] 无模型/最大隐私时回退统计兜底，仍产出可用 `Persona`。
- [ ] 增量更新沿用模块 003 语义（去重幂等、version 递增、硬规则不覆盖）。
- [ ] 素材不足层标注"原材料不足"而非编造。

### 8.2 性能验收
- [ ] 本地蒸馏 1000 条消息在设备目标档位内完成（ERD 给分档）。
- [ ] 本地推理内存 < 2GB。

### 8.3 安全验收
- [ ] 默认路径无任何网络调用（无网络环境可验证）。
- [ ] 日志不含原文/完整 API Key。
- [ ] 云端调用前有显式授权门控。

### 8.4 质量验收
- [ ] 单元测试覆盖率 > 80%（可确定性测试的部分：映射、契约、门控、兜底、增量语义）。
- [ ] `flutter analyze` 0 警告。
- [ ] LLM 输出改用**契约/结构断言 + 快照人工评审**验证（见 §9）。

## 9. 测试策略

### 9.1 单元测试
- 覆盖率目标：> 80%（针对确定性逻辑：Runtime 抽象与 mock、蒸馏产物→`Persona` 映射、契约往返、隐私门控、统计兜底、增量 merge 语义）。
- LLM 本身不可确定性复现：以 **mock/stub Runtime** 注入固定响应做确定性断言。

### 9.2 集成测试
- 端到端（mock Runtime）：`Conversation` → 蒸馏 → 映射 → `Persona` → `PersonaJsonCodec` 往返 → `PromptTemplate` 渲染。
- 兜底链路：无模型 → 统计兜底产出合法 `Persona`。

### 9.3 快照与人工评审（替代 byte-identical 确定性）
- 因 LLM 有随机性，**不做 byte-identical 断言**；改为对固定 prompt + 固定 mock 响应做**契约/结构快照**，以及对真实模型输出的**人工"像不像"评审**（≥ 3 人，用合成/授权语料）。
- 反例校验："不得编造事实"——构造原文不含某事实的语料，断言产物不出现该事实（结构/关键词层面）。
