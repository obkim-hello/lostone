# 创建模块三文档（PRD + ERD + Spec）

本技能按 Lostone 的**文档驱动开发**规范，为单个功能模块一次性生成成套的三份草稿文档，并更新文档状态追踪表。核心是保证 **PRD + ERD + Spec 三文档齐全、编号一致、日期一致**（见根目录 `CLAUDE.md` 的"🔴 三文档齐全原则"）。

## 何时使用
- 用户要为某模块新建/补齐 PRD、ERD、Spec
- 用户说"start making docs / patch docs / 写模块 00X 的三文档"
- 需要在开始编码前满足"三文档齐全"前置条件

## 关键规则（必须遵守）
1. **三文档必须成套产出**，缺一不可。禁止只写其中一两份。
2. **编号一致**：三份共用同一个模块编号（如 `002`）。
3. **日期一致**：三份文件名与正文日期相同。**草稿**用当天日期；批准后由用户改为批准日期并重命名。
4. **新建文档初始状态一律为 `📝 草稿`**，`批准日期`/`批准人` 填"待批准"。**不得自行标记为"已批准"**——批准是用户/Project Owner 的动作。
5. **产出草稿后，开发状态保持 `🚫 阻塞`**，直到三文档均被批准。
6. 遵守全局规范：源代码文件不写行内注释；文档中的 Dart 代码块保留 `///` 文档注释（`public_member_api_docs` 需要）。
7. **不要**在草稿阶段修改 `pubspec.yaml` 或写实现代码——本技能只产出文档。

## 命名约定
文件名格式：`<类型>-<模块英文名>-<编号>-<YYYYMMDD>.md`

| 类型 | 目录 | 文件名示例 | 正文模块名 |
|------|------|-----------|-----------|
| PRD | `docs/prd/` | `PRD-Data-Import-002-20260801.md` | 数据导入（Data Import） |
| ERD | `docs/erd/` | `ERD-Data-Parsers-002-20260801.md` | 数据解析器（Data Parsers） |
| Spec | `docs/spec/` | `SPEC-Data-Parser-002-20260801.md` | 数据解析器（Data Parser） |

- 三份共用**同一编号**（`002`）和**同一日期**（`20260801`）。
- 每份的英文模块名可各有侧重（PRD 偏产品、ERD/Spec 偏工程），沿用 001 的先例（Project-Setup / Flutter-Setup / Project-Config）。

## 执行步骤

1. **确认输入**。明确：模块编号、模块中文名、英文名（三份各自的）、日期（默认今天）、优先级、依赖模块。缺失且无法从 ROADMAP/上下文推断时，才向用户提问。
2. **读参考**：
   - 模板：`docs/prd/PRD-TEMPLATE.md`、`docs/erd/ERD-TEMPLATE.md`、`docs/spec/SPEC-TEMPLATE.md`
   - 范例（深度对齐）：`docs/prd/PRD-Project-Setup-001-*.md` 及对应 ERD/Spec
   - 范围来源：`docs/overview/ROADMAP.md` 中该模块所属 Phase 的任务清单
   - 现状：`docs/DOCUMENT-STATUS.md`
3. **写 PRD**：必填章节——背景与目标、用户故事（作为/我想要/以便于 + 验收标准）、功能清单（含优先级 P0/P1/P2）、非功能需求、验收标准、测试策略、风险。头部元信息填 `状态：📝 草稿`、关联 ERD/Spec 文件名。
4. **写 ERD**：必填章节——技术目标、设计约束、架构设计、**数据结构定义**（Dart 类，带 `///`）、接口设计、实现细节、测试策略、安全考虑。技术栈与工具链须与仓库实际一致（当前 Flutter 3.38+/Dart 3.11+）。
5. **写 Spec**：必填章节——接口定义（签名/输入输出规格表/前置后置条件/不变性）、数据规格、边界情况、行为规格、性能规格、**测试规格（可运行的测试用例 + fixtures）**、依赖规格、验收标准。
6. **交叉引用一致性**：三份互相在头部"关联"字段引用彼此的确切文件名；编号、日期、模块定位一致。
7. **更新 `docs/DOCUMENT-STATUS.md`**（🔴 必做）：
   - 完整性矩阵该行改为 `📝 草稿 / 📝 草稿 / 📝 草稿`，三文档齐全列 `⚠️ 草稿完成`，开发状态 `🚫 阻塞`。
   - 新增"模块 00X 详细状态"小节（文档信息表 + 三文档齐全检查 + 待办）。
   - 追加"更新记录"一行。
7b. **同步根目录 `README.md`**（🔴 必做，见 CLAUDE.md「根目录 README.md 同步规则」）：
   - 「📚 项目状态」的当前阶段与进行中清单。
   - 「📋 文档体系 → 模块文档」表：该模块 PRD/ERD/Spec 链接与状态。
8. **自检清单**（产出后核对）：
   - [ ] 三份文件都已创建，且在正确目录
   - [ ] 编号一致、日期一致
   - [ ] 三份状态均为 `📝 草稿`，未标"已批准"
   - [ ] 头部关联字段互指正确
   - [ ] DOCUMENT-STATUS.md 已更新（矩阵 + 详情 + 更新记录）
   - [ ] 根目录 README.md 已同步（项目状态 + 模块文档表）
   - [ ] 无源码/pubspec 改动
9. **收尾**：向用户报告创建的三份文件路径，并说明"当前为草稿、开发仍阻塞，需评审批准后才能编码；批准时把日期改为批准日期并重命名文件"。若用户此前用 `docs/*` 分支，提示可据此提 PR。

## 提交（仅当用户要求）
- 分支：`docs/PRD-00X-<slug>`（从最新 `main` 切出）
- Commit：`docs: 模块 00X 三文档草稿（PRD/ERD/Spec）`
- PR 标题：`[PRD-00X] <模块名> 三文档草稿`
